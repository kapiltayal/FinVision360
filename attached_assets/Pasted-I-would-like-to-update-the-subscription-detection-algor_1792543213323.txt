Subscription detection algorithm runs whenever user adds transactions via file upload or plaid. For file uploads, algorithm runs right before user previews (after all data processing/standardization and deduplication is complete) the transactions so that user has a chance to make changes.


SUBSCRIPTION DETECTION ALGORITHM

Algorithm will identify a transaction as Subscription or recurring detection. 
Recurring transactions: Same frequency  (is_recurring = TRUE and recurring_type = 'recurring_bill') 
Subscription is same amount and same frequency (is_recurring = TRUE and recurring_Type = 'Subscription')


Identify Subscription or recurring transactions in the following manner:

1. User history: User has overrides always wins. If user has tagged any transaction of this merchant as recurring or subscription then just use the same tags
2. For plaid ingestions, check if there is a recurring or subscription flag and use it for tagging
3. Deterministic matching: check the merchants table to identify if merchant is a recurring or subscription only merchant
4. Algorithmic & Heuristic Matching (The Core Engine). 

Applicable when there are at least 3 transaction from the merchant (including the historical transactions for the in the database)

Step A: Temporal & Lookback Analysis
- Calculate the `days_difference` between consecutive dates.
- Check if the interval falls into standard cycles with a grace period:
  * Weekly: 7 days (6 to 8 days)
  * Bi-weekly: 14 days (13 to 15 days) 
  * Semi-monthly: 15 days (14 to 16 days) *Note: Treat alternating 14 and 16-day gaps as Semi-monthly, not Bi-weekly*
  * Monthly: 30 days (27 to 33 days) 
  * Quarterly: 90 days (85 to 95 days)
  * Semi-Annual: 180 days (175 to 195 days)
  * Annual: 365 days (360 to 370 days)
- For 3 to 4 transactions, calculate the median days_difference and see if it falls directly into the cycle windows above. For 5+ transactions, ensure at least 80% of the intervals fall within the given cycle windows above .If they do then tag is_recurring = TRUE and recurring_freq = as determined


Step B: Variance Filtering

Calculate the median amount of the transaction cluster. If every transaction amount in the cluster is within ±5% of that median amount, flag recurring_type = 'subscription'. Otherwise, flag recurring_type = 'recurring_bill'.
